# Vendored SCCR engine

`sccr/` here is the reference implementation from `SCCR_Execution_Package.zip`,
the executable companion to Vladimir Filkov's preregistered protocol *Composing
LLM Skills Under Conflicting Instructions: A Preregistered Evaluation of
Policy-Compiled Skill Contracts and Capability-Enforced Execution* (UC Davis,
protocol dated 24 August 2026). It is MIT licensed; see `LICENSE`.

It is vendored rather than depended on so that experiment 5 runs against a
frozen copy, and so the one change made to it is visible in the diff.

## The only change

`sccr/model.py` imports `StrEnum`, which needs python 3.11. Both run hosts are
on 3.10, so the import falls back to a two-line `class StrEnum(str, Enum)` shim.
Nothing else is modified: the policy engine, conditions, reference monitor,
workflow gate, simulator and scorer are byte-identical to the package.

## What is ours

- `nodes.json` is generated by this project from `../../graph-data.js`. It holds
  the verbatim skill directives used to build the scenarios, one record per
  Network Analyzer node.
- The scenarios themselves, the runner, and the scoring wrapper live one
  directory up: `sccr_bench.py`, `sccr_enforce_check.py`, `run_sccr.py`,
  `sccr_report.py`, `demo_hook.py`.

The shipped 504-scenario scaffold is deliberately not used. Section 6.3 of
`build_findings.py` explains why: the generator writes the answer key and the
same engine checks it, so every condition's score comes out an exact seventh of
the scenario count and the full system has no path to failure.
